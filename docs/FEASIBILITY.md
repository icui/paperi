# Native feasibility protocol

Run read-only capture while the existing manager is active. Do not grant a future live manager control over the same windows concurrently with PaperWM.

1. Save a snapshot before and after each action. Record app bundle/version, OS, visible display configuration, and whether existing PaperWM was enabled.
2. Native tabs: use Finder and a daily native-tab app. Create, select, merge, detach, close active, and close last tabs. Compare AX IDs, roles, geometry and available tab counts. Establish affirmative grouping evidence before mapping physical windows into one logical slot. Equal titles/frames are insufficient.
3. Popups: record Control Center, a context menu, a modal file sheet, and the popup that blocks current management. Observe focus changes and return to a document on the other display. Capture which roles/owners are excluded and whether management recovers. An AX timeout alone is not a proven explanation.
4. Displays: capture both displays, change primary display, move a document across monitors, switch each monitor's Space, then unplug/replug. Match display UUIDs and runtime Space IDs. Screenshots should be annotated with AppKit-vs-AX coordinate conventions.
5. Space movement: a later opt-in effect prototype must validate membership before/after transfer and follow-focus with bounded cancellation. Current tools do not transfer windows.
6. Timing: release core benchmarks measure only in-memory layout. Existing-manager command latency and physical render cadence need separate timed traces/Instruments. Do not present snapshot read time as management performance.

The AX recorder subscribes existing apps/windows, follows workspace launch/termination, and attaches newly created or focused windows. Start interactions after `recorderReady`; the requested recording duration excludes initial subscription setup. Review `subscriptionFailed` entries before interpreting missing events. Apps may reject specific notifications or be unready at launch; three bounded startup retry passes attempt subscriptions and enumeration again (nominally after 1, 3, and 7 seconds; AX work can delay them). Review subscriptionRetry and subscriptionFailed records; continuous reconciliation remains pending, so repeat the capture when needed. Minimize/deminimize and application hide/show notifications are requested; fullscreen changes still require snapshot comparison and must not be inferred from resize alone. Missing notifications do not establish that an action never occurred. Titles are not included in event records.

Release gates remain open until real interactions verify native tabs, popup recovery, independent displays and no-injection Space transfer. No system settings or existing Hammerspoon configuration have been changed by this increment.

## Controlled recorder integration check

Run `ruby scripts/check-ax-recorder.rb` in a GUI session with Accessibility trust for the built CLI. It builds a disposable regular AppKit app in an ignored temporary directory, waits for `recorderReady`, launches the fixture in the background, and checks all expected launch/window/termination events and matching nonzero create/destroy IDs. The fixture changes only its own window and exits after nine seconds; the recording lasts sixteen seconds. No documents are opened or saved. Only event counts are reported, and temporary logs/bundle are removed.

Use `paperi record 30 --bundle-id identifier` for app-specific manual captures (repeat the flag for several apps). Output reaches pipes immediately. A successful fixture check validates notification delivery for that app/host only. In the initial accessory-app experiment, the fixture completed all actions but the recorder received no workspace launch/termination events, including with the full AppKit event loop. Regular-app delivery must not be generalized to newly launched accessory apps; startup enumeration and missing-notification reconciliation need separate coverage.

## Repeated diagnostic fixtures

Run `ruby scripts/check-diagnostics.rb --cycles 2 [new-output-directory]` to repeat recorder lifecycle, one native pair, multiple groups, isolated selection metadata, content-tab withholding, unvisited-member recovery, observer restart and popup policy checks. The runner executes fixtures sequentially, preserves separate machine-readable reports and build/fixture logs, updates a summary after every step, and exits nonzero if a required check fails. Existing output directories are never overwritten. Native enumeration and restart physical-inventory checks are informational only; structural, identity, cleanup and event-delivery failures still fail the run. These are controlled local fixtures, not a promotion of platform release gates.

Repeated captures exposed an important restart limitation after the initial successful source-teardown experiment: if AX enumeration succeeds with an empty window array, a replacement observer can retain no existing window roots and miss subsequent destruction notifications. Source removal can still be correct while capture coverage and binding-reset verification remain inconclusive. Preserve those failures; do not repopulate the new scope with old references or infer that the application is empty.

## Controlled panel and sheet evidence

Run `ruby scripts/check-popups.rb [new-output.json]` in an Accessibility-trusted GUI session. It starts a scoped `record --window-evidence` session before launching a disposable regular app. The app creates a normal document, shows/closes a nonactivating child panel, presents/dismisses an attached sheet, moves its document after each dismissal, then closes and quits. The fixture changes only its own windows and opens no files. Captures are local and ignored; existing output is preserved.

The collector reads roles/subroles, parent equality, move/resize capability, window level, fullscreen/minimized flags, enumeration/observer provenance and per-app focus IDs. It checks direct window/sheet/dialog children, deduplicates AX references, and limits each app to 32 window nodes, depth 2, 128 children per node and a 0.75-second budget plus an in-flight AX call. Query errors and truncation stay visible. It never reads title, label, description, text or geometry values. Missing fullscreen/minimized metadata now stays unknown; an otherwise eligible document is pending. Snapshot schema 2 uses `null` for unknown presentation flags.

On the initial host, the panel is `AXWindow`/`AXSystemFloatingWindow` and excluded; the sheet is `AXSheet` with no subrole and excluded. The document remains eligible, observer references survive both interactions, and move notifications continue after dismissal. During the sheet, the focused UI element's `AXWindow` is the document ID, but the application's focused-window ID is the sheet's own ID. Per-app focus returns to the document after sheet dismissal. The background nonactivating panel provides no affirmative document-focus return, and the app remains inactive. Do not interpret this fixture as OS active-focus recovery, management recovery, Control Center/context-menu/file-panel parity or recovery on a second display.

## Native-tab structural investigation

Run `ruby scripts/check-native-tabs.rb [new-output.json]` for eight timed stages in a disposable regular AppKit fixture: two windows, merge, select second, select first, detach, remerge, close active, close last. The harness validates the fixture's own native membership/selection/visibility and saves each stage beside a read-only `paperi tab-evidence bundle.identifier` capture. It does not infer a grouping policy or verify Finder/daily-app parity. Existing output is preserved; provide a new path for a repeat run.

The diagnostic records window enumeration errors and bounded AX structure, including `AXTabs`, children, selected children, window/top-level relationships and boolean selection values. Titles, labels, descriptions and string values are not queried. Depth/node/time truncation is explicit; local node numbers are not persistent identities. Empty successful enumeration and unsupported `AXTabs` must remain distinct from proof of an empty/closed tab group.

Initial-host finding: the fixture confirmed merge/selection/detach/close, but AX returned an empty window array with success at every stage. Making the fixture key did not change this. The captures are inconclusive for grouping. Next investigate observer-supplied window references and real daily native-tab apps; no native-tab feasibility gate is complete.

### Persistent observer capture

The harness now starts `paperi record 20 --bundle-id identifier --tab-evidence` before launching the fixture and uses its timed structural samples for all eight stages. Exactly one explicit bundle ID is required. Samples retain separate enumerated `roots` and `observedRoots`; the latter come from the recorder's native notification/discovery references and are removed on confirmed destruction. Root indices and graph node IDs remain capture-local. Each sample includes capture-start and completion uptime; a stage that changes during capture remains inconclusive. Detailed structural reads can delay callbacks and must not be used as performance measurements.

On the initial host, the persistent session exposes one active enumerated window during merge while retaining both physical member roots, then restores two enumerated windows after detach. `AXTabs` is exposed on a child `AXTabGroup`, not the `AXWindow` itself. Its two `AXTabButton` radio controls carry selection values, and the enumerated representative changes to match the fixture's selected member. Both controls' `AXWindow` relationships point to the active representative, so the graph does not directly map each control to its underlying inactive physical member. Keep this limitation explicit; grouping arbitrary apps from counts or disappearance alone remains unsupported. The difference from the earlier empty one-shot captures is observed, not explained.

### Native source teardown and observer restart

Run `ruby scripts/check-native-tabs.rb --restart [new-output.json]` for a 42-second controlled observer replacement. The recorder first learns both members of an unchanged native pair, removes its native source and workspace listeners, then starts again. `record --restart-after seconds` is an explicit diagnostic option; it must occur strictly before recording ends. Restart and final-stop JSON include native source removal evidence measured before observer ownership is released.

The initial-host check passes all 14 required checks: the old source is absent from its run loop, readiness occurs exactly once per start, create/destroy delivery is not duplicated, the new scope differs, and the unchanged pair has only one observed binding after restart. A separate `physicalInventoryComplete` check is false: AX enumeration supplies only the selected representative, so the new observer initially lacks the inactive physical root. This limitation stays visible and is not repaired by replaying old references or membership. Native source ownership also has isolated real-CFRunLoop regressions for repeated removal, independent replacement, release cleanup and suppression of a queued callback after removal. Daily-app restart recovery and full inactive-member reconciliation remain open.

Recorder runs now additionally reject workspace/native callbacks carrying an earlier run token. A deterministic retained-workspace-callback regression reproduced an old termination event affecting the restarted recorder before this guard; current-run delivery remains valid after the fix. Restart reports separate duplicate-event detection from `windowEventCoverageComplete`, so missing notifications are not mislabeled as duplicates. The repeated-diagnostics failures above remain a rediscovery gap even with correct teardown and stale-callback rejection.

Reconciliation additionally reads fresh `AXFocusedWindow` and `AXMainWindow`, validates each reference's PID and AXWindow/AXSheet role, and deduplicates equal references across discovery channels. `windowDiscovery` exposes query results and accepted-source provenance; native fixture schema 11 retains these passes. This is a fresh-reference fallback only. Unsupported focus/main attributes or an inactive app can still provide no usable references, and a recovered current representative does not establish inactive-tab membership. Old observer references are never used to fill that gap.

Both post-change restart captures pass their required checks with incomplete initial inventory. The provenance capture shows all eight focus/main reads returning -25212, with accepted references exclusively from AXWindows. It therefore does not demonstrate live fallback recovery or explain the earlier empty-enumeration failures. Isolated injected-metadata tests verify fallback filtering and deduplication without making native registrations.

### Multiple containers and enumeration failures

Run `ruby scripts/check-native-tabs.rb --multi [new-output.json]` to create five identically titled windows. The fixture forms two independent pairs and leaves one window independent, changes selection in each pair, detaches a member from the first pair, moves it into the second group (three tabs), closes that group's selected window, then closes everything. The harness verifies native ground truth and compares each AX tab group's owner/selection/count with it, including the independent window's continued identity. No titles or geometry are used to associate members.

Observer structure and enumerated representatives are separate report checks. Initial-host multiple-container captures retained all five physical roots and exposed two separately owned two-tab groups, then a three-tab group after transfer and a two-tab group after active close. Enumeration nevertheless returned an empty array throughout. This is not treated as an empty layout or a grouping success: observer structure can be verified while enumeration remains inconclusive. Cross-process assignment of inactive members to the right group and daily-app parity are still open.

### AX equality continuity across selection

Persistent captures now assign each retained AX reference an `axIdentity` token within an `identityScope` unique to its observer lifetime. Tokens use `CFEqual`, not pointer addresses or labels. At most 512 references are retained per observer; tokens are not recycled, exhaustion is explicit, and teardown releases the registry. A changed scope, missing token or exhausted/truncated capture makes cross-sample comparison inconclusive. These diagnostic tokens do not guarantee semantic identity after destruction/reuse or across process/observer restarts.

The harness's `identityComparisons` compares both fixture groups at merge, selection of the other member, and selection back. On the initial host, each group's token and both ordered control tokens remain equal across all three samples. The selected control changes and its observed owner window ID matches the corresponding physical fixture member; selecting back restores the original association. This provides affirmative observed-selection bindings in unchanged fixture groups, without titles, geometry or injected user input. It does not assign unvisited members, prove continuity through regrouping, or establish daily-app support. Production association/reconciliation remains unimplemented.

### Conservative diagnostic candidate tracker

Persistent reports expose `selectionAssociations` with `observed`, `unavailable` or `conflict` status, selected-control bindings, unresolved controls and per-candidate completeness. The graph adapter requires complete traversal/identity coverage, current physical window roots and matching group/control ownership. Learning within each group requires known boolean selection for every control and exactly one selected control. It accepts native AX result-code types as well as JSON-style integers. Missing evidence clears affected learning rather than filling gaps from spare physical roots.

Learning is scoped to an observer. Changes to the group set or ordered controls clear all learned bindings for that process; incomplete captures and confirmed window destruction invalidate them too. A control changing physical identity, two controls claiming the same window, or shared control/group identities fails closed and remains quarantined until a new scope. No deferred associations are replayed. Completeness means all controls were actually visited in the current diagnostic topology, not that a native-window group is safe to manage.

The live multiple-container check verifies that each pair is partial after the second member is first learned and complete after both have been selected. Detach/regrouping and incomplete metadata drop the old bindings; closure clears candidates. Daily-app native-vs-content-tab classification, unvisited tabs and full lifecycle reconciliation remain unresolved. This tracker does not feed the core reducer or enable any window effects.

### Isolated selection metadata failures

Run `ruby scripts/check-native-tabs.rb --partial [new-output.json]` for six windows: a two-tab group, a three-tab group and an independent window. The third member of the second group is never selected. With complete structure and ownership, that group's missing or ambiguous selection is represented by `selectionKnown: false` and `unavailableGroups`, with no bindings and no completeness. The first group can learn both visited members without being invalidated by the unrelated missing value. Recovering selection starts that group fresh; earlier bindings are never replayed. Unknown topology/control shape/ownership, identity exhaustion or traversal truncation still withholds all candidates. Current owners of unavailable groups still participate in collision quarantine, and shared identities still quarantine the observer. Topology changes and confirmed destruction continue to clear all learned bindings conservatively.

The initial-host partial fixture verifies both behaviors through the same observer, while successful AX window enumeration remains empty. Observer structure and inventory checks pass independently; no empty-layout inference or daily-app grouping claim is made. Report schema 10 adds the explicit selection-availability fields and the partial-fixture mode.

### Unvisited native member

Run `ruby scripts/check-native-tabs.rb --unvisited [new-output.json]` for a three-window native group. It selects the first two members and returns to the first before visiting the third. All three physical windows are already available through observer roots. On the initial host, however, the third control omits `AXValue` until first selected. Complete-metadata parsing therefore returns `unavailable`, with no candidate bindings; the physical inventory cannot fill the missing selection value.

Selecting the third member supplies that value and starts fresh learning with only its selected-control binding. Revisiting the first two members then completes the same group and ordered controls within the same observer scope. Closure invalidates those bindings. The nine-stage fixture uses longer intervals to capture both revisits. These checks establish safe withholding and recovery for this fixture, not support for discovering unvisited members in daily apps.

### Content-tab negative control

Run `ruby scripts/check-native-tabs.rb --content [new-output.json]` for the five-window native fixture with an ordinary two-item `NSTabView` inside the independent window. The fixture switches content selection 0→1→0→1 while also switching the native groups. The independent window must remain outside native tab membership. Harness-only ground truth separates native and content controls; no fixture ID or app exception is used by the diagnostic tracker.

Checks require the actual content `AXTabGroup` and two controls to be captured, the selected content control to match the fixture, and content candidates never to become complete. Both content controls refer to one physical window, so observing both must quarantine that group as conflicting physical-owner evidence. The mixed fixture also requires complete learning of both unrelated native groups.

The selection collector records booleans and, for `AXRadioButton`/`AXValue` only, exactly numeric zero/one as booleans with an explicit `AXValueEncoding`. It ignores other numbers and string values and does not query `AXValue` on text or other controls. This preserves useful selection metadata without treating numeric content elsewhere as selection. General native-vs-content classification and daily-app support remain open.

Read the report's retained `quarantined` flag separately from its current `status`. A regrouping capture can be `unavailable` while the prior same-window conflict remains quarantined; missing evidence must not silently clear that state. The negative-control harness verifies retained quarantine through later topology changes as well as zero complete content candidates.

Increment 18 replaces whole-scope physical-owner quarantine with group isolation. A changed control owner or duplicate physical owner blocks every implicated group; unrelated groups continue learning. Already blocked groups' currently observed owners participate in collision detection, so another group cannot claim their window. Shared or malformed AX identities still block the whole scope. Reports expose `scopeQuarantined`, retained `quarantinedGroups`, and per-candidate quarantine; blocked candidates have no bindings and never become complete. Quarantine persists through missing metadata, topology changes, disappearance and destruction invalidation until observer replacement. The mixed fixture now requires both native groups to complete while only the content group is quarantined. This remains diagnostic evidence, not native-tab classification or reducer integration.
